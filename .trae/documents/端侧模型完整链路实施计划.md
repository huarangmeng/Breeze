# 端侧模型完整链路实施计划

## Summary

- 目标：在 `Breeze` 中落地“内置端侧模型目录 -> 下载模型 -> 校验/解压 -> 加载运行时 -> 对话流式出字 -> 会话复用/释放”的完整链路。
- 平台范围：`Android`、`iOS`、`Desktop(JVM)` 首发；`Web(JS/Wasm)` 本轮明确不做端侧推理，只保留 Hosted Provider 现状。
- 推理底座：统一采用 `llama.cpp` + `gguf`，共享层只依赖抽象接口，平台层负责绑定本地运行时。
- UI 策略：保留现有 `ApiConfig` 作为 Hosted Provider 配置页；新增独立的“端侧模型”入口承载模型目录、下载进度、启停和删除；`ModelSettings` 聚焦推理参数与当前模型行为，不再承担下载管理。
- 交付标准：用户可在端侧模型页选择预置模型、查看磁盘占用、下载/恢复/删除、启动运行时，并在聊天页直接以流式方式与已下载模型对话。

- `data/src/commonMain/kotlin/com/hrm/breeze/data/llm/LocalProvider.kt`
  - 目前只是回显桩实现，没有模型目录、下载器、运行时、会话管理。

### 现有设置与导航

- `app/shared/src/commonMain/kotlin/com/hrm/breeze/ui/screens/modelsettings/ModelSettingsViewModel.kt`
  - 当前只持久化 `modelId`，参数区仍是 UI 骨架，尚未接真实推理参数。

  - 当前仅展示当前模型与模型设置入口，没有模型下载状态和运行状态感知。

### 现有平台能力

- `data/src/androidMain/kotlin/com/hrm/breeze/data/platform/AndroidPlatformContext.kt`
  - Android 已有应用级 `Context` 初始化入口，可用于模型目录、下载器、原生运行时初始化。
- `data/src/androidMain/kotlin/com/hrm/breeze/data/settings/BreezeSettings.android.kt`
  - Android 设置已写入私有目录，适合继续把模型文件放在应用私有存储。
- `data/src/iosMain/kotlin/com/hrm/breeze/data/platform/BreezePlatformPaths.ios.kt`
  - iOS 已统一到 `Application Support`，适合存放模型权重和运行时缓存。
- `data/src/jvmMain/kotlin/com/hrm/breeze/data/platform/BreezePlatformPaths.jvm.kt`
  - Desktop 已统一到平台规范的应用数据目录，适合存放 `gguf` 与运行时元数据。
- `docs/platform/persistence-paths.md`
  - 已明确各平台持久化语义，端侧模型目录应复用该策略，不单独发散路径规则。

### 明确缺口

- 缺端侧模型目录元数据和预置模型清单。
- 缺下载任务、断点续传/恢复、校验、删除、磁盘占用统计。
- 缺 `llama.cpp` 运行时抽象与 Android/iOS/Desktop 平台绑定。
- 缺运行时生命周期：预热、会话复用、并发互斥、释放、错误恢复。
- 缺端侧模型管理 UI 与状态持久化。
- 缺针对端侧模型的测试矩阵和平台验收路径。

- 现有 `modelId` 只是字符串，不足以表达端侧模型资产状态和推理能力。

做法：

- 用 `OnDeviceLlmProvider` 替换当前 `LocalProvider` 的回显逻辑。
- Provider 仅负责把 `LlmCompletionRequest` 转成端侧运行时输入，并把增量 token 透传为 `Flow<String>`。
- `OnDeviceModelCatalog` 维护内置模型清单，首版使用“代码内置 + 可升级资源文件”方案：
  - 第一阶段直接在 `commonMain` 定义预置模型列表，避免引入远程目录服务。
  - 保留后续切换到远程清单或本地 JSON 的扩展点。
- `OnDeviceDownloadManager` 负责：
  - 创建下载任务
  - 拉取 HTTP 响应流
  - 先写入 `*.partial`
  - 完成后做 SHA256 校验
  - 校验通过后原子 rename 为正式 `gguf`
  - 失败后保留可恢复信息
- `OnDeviceRuntimeManager` 负责：
  - 运行时初始化
  - 单模型单实例复用
  - 对话 session 创建/关闭
  - 加载互斥
  - 推理中取消
  - 内存不足或 native 崩溃后的状态回退
- `ChatRepositoryImpl` 增加前置校验：
  - 当前 provider 为 `Local` 时，必须确认所选模型已下载且运行时可用
  - 未就绪时返回明确错误，而不是空字符串失败

原因：

- 下载、校验、运行时生命周期不能混在 `ViewModel` 或 `Provider` 里，必须单独建编排层。

## Assumptions & Decisions

- 决策：本轮不做 Web 端侧推理，Web 继续保留 Hosted Provider 路径。
- 决策：端侧模型目录由应用内置，不依赖后端配置服务。
- 决策：端侧模型文件采用 `gguf` 单文件为主，首版不引入分片模型包管理。
- 决策：下载后必须做 SHA256 校验，校验失败一律不允许进入加载态。
- 决策：单设备同一时刻仅维护一个活跃推理任务，避免多会话并发带来的内存爆炸。
- 决策：下载任务以应用前台/进程内任务为首版能力，先不引入 Android `WorkManager`、iOS 后台传输扩展。
- 决策：Desktop 首版以当前开发环境可验证的 macOS 为必测平台；Windows/Linux 走同一目录与 native 装载结构，但运行验证放在后续补齐。
- 决策：当前 `LocalProvider` 完全升级为真实端侧 provider，不再保留回显 mock 语义；如需调试回显，单独保留测试 fake provider。

## Recommended Delivery Order

1. 先完成领域模型、设置项和数据库资产表。
2. 再完成模型目录、下载器、校验器和状态流。
3. 第三步接 `llama.cpp` runtime bridge，先跑通 Desktop(macOS) + fake download。
4. 第四步打通 Android 和 iOS 平台桥接。
5. 第五步接新导航页、下载管理 UI、聊天页状态感知。
6. 最后补测试、文档、ADR 和各平台 smoke test。

## Verification Steps

### 自动化验证

- 运行 `./gradlew :data:jvmTest`
- 运行 `./gradlew :app:shared:allTests`
- 检查 `data/schemas/` 是否导出数据库新 schema

### Android 验证

- 运行 `./gradlew :app:android:assembleDebug`
- 安装后进入端侧模型页，下载预置小模型
- 下载完成后进入聊天页发送消息，确认流式出字
- 删除模型后再次发送，确认被阻止并给出明确提示

### Desktop 验证

- 运行 `./gradlew :app:desktop:run`
- 在 macOS 上下载模型并完成多轮对话
- 切换到另一端侧模型，确认旧 runtime 被释放、内存状态恢复

### iOS 验证

- 从 Xcode 运行 `app/ios`
- 下载模型并完成至少一轮对话
- 重新启动 App，确认已下载模型状态和当前选择能够恢复

### 回归验证

- Hosted Provider 流程不回退：
  - `ApiConfig` 仍可测试远端连接
  - OpenAI-compatible 流式聊天仍可用
- 历史会话持久化不回退：
  - 本地模型对话仍写入 `Conversation` / `Message`
  - 切换 provider 不破坏历史列表展示
